# Fix: user cannot answer a claim follow-up question
Status: done 2026-11-02 (per D-036)
- **Problem:** the results page shows the follow-up question (e.g. "What specific coverage level do you have…?") but gives no way to answer it.
- **Root cause:** `ClaimResultView` renders the follow-up as a read-only `Alert`. The only input is the level picker, which shows only when `needsCoverageLevel` is true with tiers listed. Since D-035, a level question with no tiers becomes `needsCoverageLevel: false`, so the page has no input at all.
- **Change (frontend only, per D-036):** whenever `followUpText` is shown and the level picker is not, render an answer form under it: a labelled multiline text field (required, trimmed, with a character counter) and a **Submit answer** button. Submitting calls `evaluateClaim(contractId, composed, claim.coverageLevelRequested ?? null)`. `composed` = original claim text + blank line + the follow-up question + the answer, built by a pure helper in `src/api/claims.ts` (or `src/lib`). Labels come from `claimStrings` constants and must not be hard-coded literals. The answer's max length is set so that `composed` ≤ 2000 chars (`claimRules` constant). Busy/reset/error behaviour matches `reevaluate` (reset after `router.push`, `FieldError` for problems, `aria-busy`, `role="status"` wait note). New test IDs go in `testIds`.
- **Owner:** frontend. No endpoint, schema or backend change.
- **Regression test (Vitest):** an `InsufficientInformation` result with `followUpQuestion` set, `needsCoverageLevel: false` and empty options renders an answer field. Typing an answer and submitting POSTs a `claimText` that contains the original text, the question and the answer, then navigates to the new claim. The test must fail on the current code. Add a unit test that the helper caps composed text at 2000 chars.
